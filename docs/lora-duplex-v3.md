# LoRa v3 双向命令与可靠结果反馈

日期：2026-10-10。本文件描述终端板软件与主机模拟行为，不代表无线实物联调已完成。网关仅增加可复用的纯 C 命令事务核心，尚未建立网关板工程、ESP8266 或巴法云接入。

## 本轮完成内容

- 终端空闲连续接收，发送结束返回 RX；DIO1 ISR 只记录事件。
- RX 前台读取带容量检查；RF CRC、头错误、超时或过长帧不进入执行器逻辑。
- v3 帧头、地址/会话/事务校验、业务参数范围和命令有效期。
- 固定命令结果缓存、事务高水位、重复结果重发，不重复执行命令。
- 遥测/HELLO/RESULT 等待匹配 ACK，最多三次发送；命令在网关等待 RESULT。
- 结果优先于普通遥测；有界结果队列满时拒绝处理新命令，不先执行后丢结果。
- OLED 通信页显示射频 RX/TX、网关在线、ACK、重试和命令计数。
- 原有本地 MANUAL/AUTO/SAFE、泵时间上限/冷却、数据失效保护保持有效。

## 通用帧格式

**无线协议由裸 v2 改为 v3，不与此前的裸 34 字节帧兼容。** 原 v2 遥测编码仍作为 v3 遥测的内层负载。

全部多字节字段小端，最大帧 96 字节：

| 偏移 | 长度 | 含义 |
| --- | --- | --- |
| 0 | 1 | 帧头 A5 |
| 1 | 1 | 版本 3 |
| 2 | 1 | 类型：1 HELLO，2 TELEMETRY，3 COMMAND，4 RESULT，5 ACK |
| 3 | 1 | 标志：1 等待 ACK，2 等待 RESULT，ACK 自身为 0 |
| 4 | 2 | 源地址：网关 0，当前终端 1 |
| 6 | 2 | 目标地址；命令不接受 FFFF 广播 |
| 8 | 2 | 序号，允许回绕 |
| 10 | 1 | 负载长度 |
| 11 | 1 | 保留，必须为 0 |
| 12 | 4 | 当前节点会话号，非 0/FFFFFFFF |
| 16 | 4 | 非零事务号；同一方向单调增加，不回绕复用 |
| 20 | N | 负载，最多 74 字节 |
| 20+N | 2 | CRC16/Modbus，计算前 20+N 字节，低字节在前 |

CRC 与地址/会话检查是误码、误路由与旧事务过滤，**不提供加密或身份认证**。

### HELLO：8 字节负载 / 30 字节帧

- 0～3：终端 `HAL_GetTick()` 毫秒时基。
- 4～7：已处理网关命令的事务高水位。

上电第一次射频初始化通过后，使用 LLCC68 随机寄存器生成会话号；零/全1时不进入 ready。射频重连沿用该会话和去重缓存，不把重连当成新启动。该会话值不是密码学凭证，也不保证绝无碰撞。

### TELEMETRY：38 字节负载 / 60 字节帧

- 0～33：此前定义的遥测 v2 内层帧，包括其有效标志、设备输出和内层 CRC。
- 34～37：已处理网关命令事务高水位。

默认新遥测周期为 5 秒；失败重试和优先结果回传期间实际周期会延长，不承诺精确 5 秒无线送达。无效数据负载写零且清有效位。

### COMMAND：6 字节负载 / 28 字节帧

- 0：操作码。
- 1：绝对设置参数。
- 2～5：按终端毫秒时基表示的截止时间。

| 操作码 | 功能 | 参数与限制 |
| --- | --- | --- |
| 1 | SET_MODE | 0 MANUAL、1 AUTO、2 SAFE；远程不能解开本地紧急停止/泵超时锁 |
| 2 | SET_FAN | 0～4 档，仅 MANUAL 允许 |
| 3 | SET_PUMP | 0 关、1 开；仅 MANUAL，仍要求土壤有效、冷却结束 |
| 4 | SET_MUTE | 0 不静音、1 静音；不是 toggle，不清故障 |
| 5 | STOP_ALL | 参数必须 0；停止泵/风扇并锁存 SAFE |
| 6 | GET_STATUS | 参数必须 0；获取当前驱动状态 |

网关使用最近 HELLO 或遥测估计终端时基，再加本次 TTL（最大 30 秒），不是使用网关本地毫秒值直接当节点截止时间。超期或超过允许有效期的命令拒绝。**本轮没有墙上时钟同步或云端定时功能。**

### RESULT：22 字节负载 / 44 字节帧

| 负载偏移 | 内容 |
| --- | --- |
| 0 | 原操作码 |
| 1 | 原设置参数 |
| 2 | 结果状态码 |
| 3 | 执行后的模式 |
| 4 | 继电器输出指令 |
| 5 | 风扇档位 |
| 6 | 蜂鸣器输出指令 |
| 7 | 执行器就绪位 |
| 8～9 | 风扇占空比千分比 |
| 10～11 | 告警位图 |
| 12 | bit0 静音，bit1 自动灌溉启用 |
| 13 | 保留0 |
| 14～17 | 首次处理时的终端毫秒时基 |
| 18～21 | 已处理命令事务高水位 |

状态码：0 成功；1 参数无效；2 模式拒绝；3 传感器无效；4 冷却中；5 未就绪；6 已过期；7 旧事务；8 本地安全锁。

业务拒绝也会完成网关事务，但绝不是执行成功。重复命令回传第一次结果，可能是过去的输出快照；实时状态应以新的 GET_STATUS 或遥测确认。没有转速、流量等反馈，结果成功仅表示命令经业务校验并应用到输出指令。

### ACK：3 字节负载 / 25 字节帧

- 0：被确认帧类型（HELLO/TELEMETRY/RESULT）。
- 1～2：被确认帧的线缆 CRC。

同时回显被确认帧的序号、会话和事务号，交换源/目标。所有字段和被确认帧CRC匹配后才确认。ACK 不再请求 ACK，避免确认循环。COMMAND 必须收到 RESULT，普通链路 ACK 不能证明执行。

## 重试、去重与背压

- TX_DONE 后进入 2000ms ACK/RESULT 等待，超时后退避100ms重发，最多3次；同一事务字节完全相同。
- 收到匹配的迟到回复，在下一次实际发送前仍可完成事务。
- 缓存最近8个命令的完整结果。重复命令不调用控制接口，不刷新水泵计时/风扇租约。
- 同事务改变操作码、参数、截止时间或序号是冲突：丢弃并统计，不覆盖原结果。
- 缓存淘汰后仍保留高水位，旧事务返回7，不再次执行。
- 结果队列最多4条外加正在可靠发送的一条。队列无空位时不执行新命令，网关可按原事务重试。
- 收到命令结果时可抢占普通遥测/HELLO的ACK等待，优先回传结果；在途无线发送不能被中断。
- 网关串行发命令，缓存当前和上一条RESULT，ACK丢失时重复确认。网关重启先从节点高水位同步事务游标。
- 同一节点会话的事务号达到FFFFFFFF后不复用，后续需新节点上电会话。
- ACK重试耗尽仅记录通信错误和离线状态，不无限阻塞本地控制，也不能断言对端完全没执行。

## 网关事务核心接口

`gateway_command.c/.h` 不依赖 HAL，可复用到后续网关工程或主机工具。它还不是网关板完整固件。

```c
GatewayCommand_Init(&client, node_id, hello.session);
GatewayCommand_ObserveNode(&client, &hello); // 先同步命令事务高水位
GatewayCommand_Begin(&client, client.last_transaction + 1U, seq,
    LORA_COMMAND_FAN, 4U, estimated_node_tick, 10000U, local_now);
```

主循环使用 `LoraReliable_NeedsSend/MarkSending/TxFinished/Tick` 管理发送和超时；收到解码后的RESULT调用 `GatewayCommand_AcceptResult`，得到需发送的ACK。读取 `client.result.payload[2]` 判断业务是否成功，不根据CONNECTED/TX_DONE判断执行成功。

网关应先确认节点当前会话、基于新鲜时基构造命令，并保存/同步事务游标。控制前置确认、未知结果重查、节点表以及实际串口驱动由下一阶段网关软件完成。

## 当前限制

- 单节点/单网关、固定地址、串行事务；没有 Mesh、组播或多节点冲突调度。
- 无身份认证、加密、Flash去重持久化。不同上电会话由会话号隔离，但随机值仍有碰撞可能。
- 节点服务只在本地执行器关闭、按键释放时重试较长的射频初始化；SPI/BUSY/I2C/DHT22仍有有界同步过程，不是硬实时。
- 连续RX切到TX/待机读FIFO存在半双工盲区，由协议重试恢复，尚未实测丢包。
- OLED网关在线依据匹配ACK或当前会话的网关命令，15秒未活动转离线；不是WiFi/云端在线状态。
- 本轮没有烧录、RF频率/功率实测、RSSI测量、网关板联调、ESP8266或云端测试。
