# LoRa 双向控制切片设计

用户在完成终端本地控制后要求“开始下一步”。本次只实现终端双向协议、可复用的纯 C 网关命令事务核心及主机模拟，不创建网关 CubeMX 工程，不连接开发板，不接 WiFi/云端。

## 协议边界

- 采用 v3 通用信封：20 字节头 + 最多 74 字节负载 + 2 字节 CRC，最大 96 字节。
- 头字段：A5、版本3、类型、标志、源地址16、目标地址16、序号16、负载长度8、保留0、节点会话号32、事务号32；全部小端。
- HELLO、TELEMETRY、RESULT 请求 ACK；COMMAND 请求业务 RESULT；ACK 不再确认。
- v2 的 34 字节遥测保持为 v3 TELEMETRY 内层负载，不能与旧裸 v2 无线帧混用。
- HELLO 负载携带节点毫秒时基和已处理命令高水位；TELEMETRY内层34字节后也追加4字节高水位。网关重启后先同步游标，禁止从事务1重用。命令负载为操作码、绝对参数、节点时基截止时间32；时钟不用同步，但网关需根据新 HELLO/遥测更新估计。
- COMMAND 必须单播到当前节点、来自固定网关0、携带当前会话号、非零递增事务号；超时上限30秒，过期拒绝。
- 会话号在本次上电首次射频初始化时从 LLCC68 随机寄存器获取；零/全1拒绝重试，射频重连保持会话与去重记录。会话号不是身份认证，不保证密码学随机或绝无碰撞。
- RESULT 回传操作码、参数、状态码、模式、输出和告警，以及执行时刻和命令高水位，共22字节；这是驱动输出指令快照，不是物理出水/转速确认。

## 可靠性和资源

- 单个可靠发送槽，最多3次发送，TX_DONE之后才开始2秒ACK等待；重试保持原字节和序号。
- ACK 同时匹配源/目标、类型、序号、会话、事务和被确认帧CRC，迟到/错配ACK不完成事务。
- 网关COMMAND等待匹配RESULT而非普通ACK；匹配业务拒绝也是事务完成，不能报告为执行成功。网关收到RESULT后ACK，重复RESULT再次ACK。
- 终端缓存最近8个命令结果，匹配事务只重发，不再次操作执行器。缓存淘汰后仍保留事务高水位，较旧事务拒绝，避免旧泵命令重新启动。
- 相同事务但操作码/参数/截止时间/序号不同视为冲突，丢弃并统计，不覆盖原结果。
- 保留4条待回传结果；没有结果空间就不执行新命令。待回传结果可抢占等待普通遥测ACK的槽位，控制结果优先于普通遥测；单节点/单网关串行控制，不实现多节点无线调度。
- SET_MODE、SET_FAN、SET_PUMP、SET_MUTE、STOP_ALL、GET_STATUS。全部使用设置指令，不使用toggle。
- 远程命令不能解除本地紧急停止/泵超时锁；只允许本地确认模式切换解锁。原有运行时限、冷却、无效数据保护始终有效。

## 接收和恢复

- 增加连续RX和有容量参数的前台读取接口；DIO1只置标志，RX_DONE/CRC/HEADER_ERROR/TIMEOUT前台处理。
- 发送结束返回接收；FIFO读取前进入待机，校验长度，RF CRC错误不进入命令层。
- ACK丢失有限重发，耗尽后保持本地控制并继续新的周期上报；射频I/O失败只在输出关闭、按键释放时重新初始化。
- OLED通信页区分芯片ready、网关online、ACK与重试计数，不能将TX_DONE认作送达。
